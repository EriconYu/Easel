# 个人专业工作台

## 目标

服务“紫微斗数命理师”这一主画像，把研究、热点判断、内容生产、发布与复盘串成每天可执行的工作流。它是本人的专业工作台，不是通用自媒体 SaaS，也不以向上游提交 PR 为目标。

## 每日输入

- 今日意愿：关系、事业、财富、人生选择、国学哲思或自定义主题。
- 时间预算：30 分钟、1 小时、2 小时、半天。
- 内容目标：研究、选题、母稿、口播、多平台改编、发布或复盘。
- 平台偏好与禁区：当天想做的平台、暂时不想碰的主题。

## 推荐链路

1. 采集近期热点、行业资讯、用户问题和历史内容。
2. 标准化来源：标题、来源平台、URL、发布时间、热度、证据状态。
3. 读取当前画像、今日意愿、历史重复和已验证入口。
4. 按账号匹配、受众匹配、意愿匹配、时效、可表达空间、来源可靠性、风险和制作成本排序。
5. 输出最多五个推荐卡；不足五个时不硬凑，用常青选题补充并明确标记。

## 推荐卡必须包含

- 主题与来源；
- 为什么现在推荐；
- 为什么适合本人；
- 可采用的命理、心理学、人文哲学切入点；
- 适合的平台和内容形式；
- 预计制作时间；
- 事实、解释与推断的边界；
- 风险提示；
- `生成母稿`、`生成口播`、`生成平台稿`、`加入今日安排`、`不感兴趣`操作。

## 执行链路

推荐方向 → 用户选择 → 研究简报 → 母稿 → BK Content Creator 审核与改写 → 平台版本 → 人工审核 → 人工发布 → 链接和数据回填 → 复盘。

每个选题使用稳定的 task_id 贯通推荐、产物、排期、发布和反馈，不能靠标题重新匹配。

## 第一阶段改造范围

- 在 Dashboard 增加今日意愿和时间预算输入；
- 增加个性化五方向推荐区；
- 推荐卡保留来源和解释；
- 复用现有热点采集、画像、内容库和创作入口；
- 生成内容时传入完整来源与推荐上下文，而非只传热点标题；
- 生成今日任务清单，支持待做、进行中、已完成、阻塞；
- 不自动发布，不把生成完成当成已发布；
- 不把 DeepSeek 写死为唯一搜索供应商，搜索和模型调用分层。

## 验收标准

- 没有今日意愿时，系统明确提示补充，不假装个性化；
- 每个推荐方向可追溯到来源或明确标记常青选题；
- 推荐理由能指出画像、意愿和历史内容的具体依据；
- 选择方向后能生成母稿或进入 BK 内容创作流程；
- 今日任务状态能读回，重启后不丢失；
- 原创、草稿、发布、数据和咨询反馈分开记录；
- 真实来源失败时展示失败或陈旧状态，不返回伪造空榜；
- 默认单测离线且不触碰真实模型、账号、凭证和私人内容；真实模型验收另行显式运行，留存待审核样稿，不触发发布。

## 专业资料与 Skill 引用（设计原则；实际范围见第二阶段）

每条选题的创作讨论需要同时提供“选用 Skill”和“引用资料”入口。Skill用于约定方法与流程，不自动视为可靠事实来源；参考资料支持用户授权选择的本地文档、书籍章节、历史稿件和网页链接。读取范围按项目授权，不默认扫描全部私有目录，不修改原始资料。

资料应记录标题、作者/流派、版本、路径或URL、引用片段及定位（页码、章节或段落），并保留引用时版本或片段快照。扫描件/OCR应标识识别状态，不编页码。引用位置只证明文本存在，不能自动证明观点正确。

创作时明确区分：原文引用、转述、用户观点、AI推断。专业断言尽可能关联支持片段，缺依据标待核验；不得伪造书名、引文或参考编号。紫微不同流派分开标记，冲突并列提示，由用户选择本项目口径，不擅自混合；命理文献不当作心理学或医学的实证。

用户可以指定本项目“仅使用已选资料”或“允许联网补充”。严格资料模式中无依据则留空并询问，不凭模型记忆补专业结论。自动输出是待核对，不用模型自评分取代专业审核；重要引文/事实待核验时不静默称作已审核。讨论润色保留来源关联，重要判断改动后重新检查，不让后续改写丢失条件与例外。

交付界面包括正文、依据、待核验问题三部分。用户能从段落查看原始片段并指示修订；内部依据不要求原封不动塞进口播或公开成稿。不得自动上传未授权客户资料、未授权全文书籍或私人知识库到远程模型；引用范围与模型传输范围须说明。

## 已实现的第二阶段：持续创作与选用依据

- 首页显式选择近1/3/7天，勾选真实联网搜索；当前复用已配置的Codex底座（仍产生模型调用费用），不是DeepSeek搜索API。独立搜索在临时只读工作目录运行，关闭shell、代理、插件等非搜索工具；必须收到真实web_search事件，并逐条取得工具结构化来源或独立读取网页才收录；仅有模型消息的链接不能冒充搜索命中，模型给出的日期不作证据。不足、失败和日期未知均明示，不编造五条热点。
- 规则推荐与“AI分析选题”分开。后者复用当前模型；Codex以JSON Schema把task_id限定到现有候选。模型可拟创作标题、解释角度，原线索标题与URL保留；不会把分析结论当作新闻事实。
- 每题“讨论与资料”保存本人观点、Skill选择、资料选择、粘贴摘录和严格/联网边界；自动保存为任务，不因刷新推荐丢失。讨论、母稿、口播、平台稿复用同一个session_id及底座原生历史，不只在侧栏假续聊。
- Skill目录来自项目builtin、custom和本机Hermes skills。只发送勾选的SKILL.md摘录，不会宣称执行未选择Skill；其支持文件不会全量扫描发送，所需章节可以作为命名摘录补充。Skill是方法约束，不是权威事实证明。
- 文档目录受控在本机“自媒体/参考资料”和outputs/历史文案库。拒绝符号链接、越界路径及大文件；MD/TXT、DOCX用现有能力提取，PDF仅在已安装pypdf时可选，不自动装依赖；扫描件不做假OCR。可粘贴命名摘录。网页搜索线索不是已经通读的参考正文。
- 仅发送所选文档的有限片段，存储实际片段、提取行/段位置、路径、sha256和截断标识。未取得的书籍作者、版本和原书页码不自动猜测，用户可在命名摘录或观点中补充。
- 引用原文可在面板展开查看。模型被要求区分原文、转述、本人观点、推断，并给内部依据与待核验事项；引用支持强度与流派冲突仍需本人审定，不自动标为已审核。
- Codex创作会话按服务器保存的简报启用/禁用原生web_search；同线程切换边界走thread/resume保留历史。其他底座仅收到资料边界提示词，不能声称已强制关闭其全部联网能力。
- 回复正文用明确标记包裹，取回对话稿时优先只提取正文，内部依据保留在原对话和快照。没有标记时明确提示手动核对，避免把本机路径或内部说明当公开稿。
- 每次另存版本都写唯一MD文件并原子更新状态，连同当时的简报、Skill与引用快照保存；历史版本可以加载，不覆盖原文。输出仍位于共享outputs/主题-task_id/。
- 任务保留手动状态、阻塞备注及发布链接。已有内容库、发布中心与公众号草稿能力复用，不自动发布、扫码或群发。公众号真实账号投递尚未验收。

## 已实现的第一阶段行为

Dashboard 的独立 WorkbenchPanel 提供透明规则推荐（不是 AI 模型排序）：以今日意愿的中文双字子串与英文完整词命中，六维画像中的语义主题加权，并展示具体命中。零意愿匹配的新闻不进入推荐；无匹配时仅提供一个围绕意愿的常青问题，明确无新闻证据。跨源同题保留来源列表；来源发布时间与采集时间缺失时明示。反馈按画像持久化，后续推荐排除同题。

三种生成按钮通过 context API 取得完整画像、来源、意愿、格式、平台及预算内三步计划；App 创建会话、先保存绑定 session_id 的 doing 任务，再调用现有对话流生成。产物约定写入 `outputs/主题-<task_id>/`，流结束不自动完成任务。用户可保存 todo/doing/done/blocked、阻塞备注、产物路径和发布链接，刷新通过 GET 读回。

工作台文件位于 `outputs/_workbench/<persona>/state.json`。GET 不创建文件，读改写均在进程锁内，mkstemp 加原子替换防止半写；损坏文件和符号链接明确拒绝。实际模型生成质量仍需在配置好模型的会话中人工验收；离线测试验证上下文和接线，不声称验证了模型产物或真实网络采集。
