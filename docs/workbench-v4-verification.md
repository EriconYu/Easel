# 工作台 v4：统一内容项目流程与验收

## 产品收敛

唯一主线：灵感／热点／联网线索 → 持久内容项目 → 讨论与创作依据 → 独立稿件版本 → 平台适配 → 关联日历排期 → 发布页人工审核与交付。

- 首页只提供概览、来源页入口与继续已有项目，不再嵌完整选题操作区。
- 热点雷达保留画像推荐和原始榜单；基础推荐、联网补充、AI分析分别由用户点击触发。打开页面只读取已保存结果，不自动调用模型。
- 基础推荐为热榜加规则匹配，不称为 AI；搜索来源、热榜来源、常青补位和模型分析分别标识。常青不伪装成实时热点。
- 灵感收件箱保留原始输入、检索、备注、整理状态、表现记录与归档；已有项目直接复用，不再各自生成和编辑稿件。
- 内容库的项目视图统一复用讨论编辑器、显式引用、不可变版本与用户手动进度；文件浏览仍保留。
- 对话显示所属项目并可返回；没有项目的普通对话明确说明不会自动保存为项目版本。
- 项目中明确选择创作目标平台。交付与排期必须明确选择服务端真实版本，不默认使用未保存的编辑区正文。
- 日历关联画像、项目和版本，能返回项目；重复创建同一排期幂等。排期不是定时执行，不会自动发布或自动完成项目。
- 发布页收到所选版本后，须显式载入；覆盖现有编辑内容需要确认。项目原稿不被覆盖；清空文案同步清除旧项目关联。
- 搜索供应商配置集中在设置页；推荐页只读显示所选通道和分析引擎。搜索与正文模型配置独立，无静默供应商切换。
- 删除含义不清的默认“30分钟”和硬编码完工估时；旧接口时间偏好字段仅保留兼容。

## 状态与数据保护

项目进度、灵感整理状态、计划排期和平台执行结果分别记录，不相互冒充。

重复 POST 若试图改变原排期的状态、链接或备注，返回冲突而非假成功。发布页保存或人工回填主动更新适当的原排期并读回确认；多个待发布排期无法确定时要求用户选择，不猜测。已发表记录不能被存草稿降级。

公众号建草稿不标为发表。平台名称归一后匹配关联排期；已有计划可以保留 scheduled，同时单独记录实际草稿状态。此修复的公众号端到端接口测试使用隔离文件和模拟平台子进程，不代表真人送草稿箱验收。

日历 JSON 损坏时停止写入，不以空列表覆盖；保存使用独占临时文件、flush/fsync 和原子替换。

个人画像、原稿、登录态、Cookie、运行配置和私人验收产物不提交。受保护内容按既有清单逐文件核验。
